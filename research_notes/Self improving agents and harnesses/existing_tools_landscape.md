# Existing tools landscape: self-improving coding-agent setups (as of 2026-11-18)

Method notes for the report writer:

- All GitHub star counts, last-push dates and archived flags were read from the GitHub REST API on **2026-11-18** and are cited to the repository URL. "Last push" is the repository `pushed_at` field (any branch), not the last release.
- Several repositories have been renamed since earlier coverage; the API resolved the old names to: `affaan-m/everything-claude-code` -> `affaan-m/ECC`; `All-Hands-AI/OpenHands` -> `OpenHands/OpenHands`; `block/goose` -> `aaif-goose/goose`; `steveyegge/beads` -> `gastownhall/beads`; `ruvnet/claude-flow` -> `ruvnet/ruflo`; `campfirein/cipher` -> `campfirein/byterover-cli`.
- Mechanism descriptions come from each project's own README or docs unless marked "third-party". Where a README was summarised by a fetch tool and the page was silent on a point, that is recorded as "not stated", not as "no".
- Web search and fetch were rate-limited part-way through; items I could not verify from a primary source are in the Gaps sections, not in Cited Findings.

## 1. Which Claude Code plugins, skills, hooks collections and community projects implement reflection or learning loops?

### Takeaway
The space is crowded and has a dominant shape: capture signals from sessions (regex on corrections, hook-observed tool calls, transcript mining), distil them with an LLM, and write prose back into context (CLAUDE.md, memory files, skills, a SQLite store injected at session start). Human approval is common in the smaller tools and absent in the largest ones, and almost none documents an undo for an applied learning; none that I found records its writes in a manifest that supports clean uninstall.

### Cited Findings

**Built into Claude Code and Anthropic's official plugin directory**

- Claude Code ships "auto memory": "notes Claude writes itself based on your corrections and preferences", stored per repository at `~/.claude/projects/<project>/memory/`, machine-local, with the first 200 lines or 25KB of `MEMORY.md` loaded every session. Files are "plain markdown you can edit or delete at any time"; there is no approval step, only a `/memory` browser and an `autoMemoryEnabled` toggle. — [Claude Code docs: memory](https://code.claude.com/docs/en/memory)
- The same page states both CLAUDE.md and auto memory are treated "as context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead", and recommends "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." — [Claude Code docs: memory](https://code.claude.com/docs/en/memory)
- Anthropic's official plugin directory (47,555 stars, last push 2026-11-17) includes `claude-md-management`: a `claude-md-improver` skill that "audits CLAUDE.md files against current codebase state" and a `/revise-claude-md` command that "captures learnings from the current session". Both are manually invoked. — [anthropics/claude-plugins-official](https://github.com/anthropics/claude-plugins-official), [claude-md-management README](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/claude-md-management)
- The same directory includes `claude-code-setup`, which scans a codebase and recommends "the top 1-2 automations in each category" (MCP servers, skills, hooks, subagents, slash commands) and is explicitly "read-only - it analyzes but doesn't modify files". — [claude-code-setup README](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/claude-code-setup)
- The same directory includes `hookify` (see section 3) and `ralph-loop`, a Stop-hook implementation of the Ralph technique in which "the prompt never changes between iterations" and Claude "autonomously improves by reading its own past work in files"; this is task iteration, not configuration learning. — [ralph-loop README](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/ralph-loop)
- Third-party guides describe a built-in `/insights` command that analyses locally stored sessions and produces an HTML report with a friction analysis and suggested CLAUDE.md rules; one guide cautions the suggestions are "pattern-matched from repetition, not verified as correct". I did not find an official doc page for it. — [vincentqiao blog](https://blog.vincentqiao.com/en/posts/claude-code-insights/), [SSW rule](https://www.ssw.com.au/rules/use-claude-insights)

**Correction-capture and CLAUDE.md updaters**

- **claude-reflect** (BayramAnnakov): 1,959 stars, last push 2026-10-03, v3.3.1. Four hooks: a per-prompt capture hook queues detected corrections, a pre-compaction backup, a session-start reminder and a post-commit reminder. Regex detects corrections, positive feedback and `remember:` markers; `/reflect` adds a semantic filter and a 0.60-0.95 confidence score. Writes to `~/.claude/CLAUDE.md`, project and subdirectory `CLAUDE.md`, `.claude/commands/*.md`, and `AGENTS.md` if present. Human approval is required: `/reflect` offers Apply, Edit or Skip. `/reflect --dedupe` consolidates similar entries; `/reflect-skills` mines repeated requests across sessions into draft command files. No undo or rollback is described; `/skip-reflect` only discards the queue. — [BayramAnnakov/claude-reflect](https://github.com/BayramAnnakov/claude-reflect)
- claude-reflect issue #12 (closed, opened 2026-01-11) asked for size awareness because "the tool currently appends learnings without any awareness of CLAUDE.md size limits" and the author wanted "to make sure the self-learning loop doesn't eventually degrade Claude's performance by bloating the instru[ctions]". Issue #8 asks whether changing CLAUDE.md always requires human review. — [issue #12](https://github.com/BayramAnnakov/claude-reflect/issues/12), [issue #8](https://github.com/BayramAnnakov/claude-reflect/issues/8)
- **pro-workflow** (rohitg00): 2,962 stars, last push 2026-09-29. Corrections become rules via a proposed-rule flow ("You approve") or `/learn-rule`; a Stop hook captures `[LEARN]` blocks. Storage is a single SQLite database at `~/.pro-workflow/data.db` with FTS5 search; rules are auto-loaded by a SessionStart hook. Claims such as "Correction rate near zero" and "After 50 sessions you barely correct anything" appear as illustration, with no measured data. The README does not say learned rules become hooks or checks. — [rohitg00/pro-workflow](https://github.com/rohitg00/pro-workflow)
- **claude-code-auto-memory** (severity1): a plugin that automatically updates CLAUDE.md when Claude Code makes changes, separating AUTO-MANAGED sections from content it never touches (search-result description; I did not fetch the repository). — [severity1/claude-code-auto-memory](https://github.com/severity1/claude-code-auto-memory)

**Observation-based "instinct" and skill-extraction systems**

- **ECC (formerly everything-claude-code)**: 305,229 stars, last push 2026-11-17. Its `continuous-learning-v2` skill observes via PreToolUse/PostToolUse hooks (`observe.sh`), on the stated ground that "Hooks fire 100% of the time, deterministically". Raw observations go to `projects/<hash>/observations.jsonl` under `~/.local/share/ecc-homunculus/` (deliberately outside `~/.claude`); instincts go to `instincts/personal/` or `instincts/inherited/`. Confidence runs 0.3-0.9, with 0.7 described as "Auto-approved for application". A Haiku background observer is disabled by default, runs every 5 minutes, needs 20+ observations, and requires WSL2, Linux or macOS. Instincts auto-promote from project to global when the same ID appears in 2+ projects with average confidence >= 0.8. `/evolve` clusters instincts into skills, commands or agents under `evolved/`. The doc describes no approval gate and no rollback. — [continuous-learning-v2 SKILL.md](https://raw.githubusercontent.com/affaan-m/ECC/main/skills/continuous-learning-v2/SKILL.md), [affaan-m/ECC](https://github.com/affaan-m/ECC)
- **Claudeception** (blader): 2,465 stars, last push 2026-02-21 (looks dormant). A skill plus an activation hook: "When Claude Code discovers something non-obvious (a debugging technique, a workaround, some project-specific pattern), it saves that knowledge as a new skill"; the hook "ensures it evaluates every session for extractable knowledge". — [blader/Claudeception](https://github.com/blader/Claudeception)
- **Continuous-Claude-v3** (parcadei): 3,951 stars, last push 2026-11-16. "Hooks maintain state via ledgers and handoffs"; "Memory system recalls + daemon auto-extracts learnings"; motto "Compound, don't compact". — [parcadei/Continuous-Claude-v3](https://github.com/parcadei/Continuous-Claude-v3)

**Session memory stores (recall, not configuration change)**

- **claude-mem** (thedotmack): 117,923 stars, last push 2026-11-17, README badge v15.19.0, Apache-2.0. Hooks "hand each tool call (what it reads, edits and runs) to a small local worker", a local HTTP service managed by Bun; "a second agent turns that activity into short observations, and writes a summary when the session ends". Storage is SQLite at `~/.claude-mem/claude-mem.db` plus Chroma for semantic search. The next session "starts with a short index of what matters". Privacy: `<private>` tags, opt-in cloud sync, but "Anonymous usage analytics are on by default". Requires Node, with Bun and uv auto-installed. No per-memory approval is described. — [thedotmack/claude-mem](https://github.com/thedotmack/claude-mem)
- claude-mem's adoption grew fast: third-party snapshots recorded 46.1K stars in April 2026 and 83.9K on 2026-06-23. — [Augment Code, April 2026](https://www.augmentcode.com/learn/claude-mem-46k-stars-persistent-memory-claude-code), [Augment Code, June 2026](https://www.augmentcode.com/learn/claude-mem-v13-persistent-agent-memory)
- **claude-subconscious** (letta-ai): 2,913 stars, last push 2026-09-25. A background Letta agent that "watches every Claude Code session transcript" and "whispers guidance" before each prompt; "Nothing is written to CLAUDE.md". The README now labels it a "demo app ... not intended to be used in production" and redirects to Letta Code. — [letta-ai/claude-subconscious](https://github.com/letta-ai/claude-subconscious)
- Other memory layers with Claude Code integrations and current activity: claude-supermemory (2,804 stars, last push 2026-11-16), basic-memory (4,612, 2026-11-17), mcp-memory-service (2,135, 2026-11-17), memsearch (2,893, 2026-11-13), Hindsight "Agent Memory That Learns" (61,575, 2026-11-17), OpenViking "Self-evolving Context Database" (42,375, 2026-11-17), beads (28,802, 2026-11-17). Descriptions are the repositories' own taglines; I did not verify their mechanisms. — [supermemoryai/claude-supermemory](https://github.com/supermemoryai/claude-supermemory), [basicmachines-co/basic-memory](https://github.com/basicmachines-co/basic-memory), [doobidoo/mcp-memory-service](https://github.com/doobidoo/mcp-memory-service), [zilliztech/memsearch](https://github.com/zilliztech/memsearch), [vectorize-io/hindsight](https://github.com/vectorize-io/hindsight), [volcengine/OpenViking](https://github.com/volcengine/OpenViking), [gastownhall/beads](https://github.com/gastownhall/beads)

### Inferences
- The "learning" output of nearly every Claude Code tool is more prose in context. Anthropic's own docs say that prose is "context, not enforced configuration", so these tools improve recall but cannot guarantee behaviour.
- There is an inverse relation between adoption and human control in this sample: the two largest learners (ECC, claude-mem) write without per-item approval, while the approval-gated tools (claude-reflect, pro-workflow) are two orders of magnitude smaller. Star counts at this scale may also reflect bundle popularity rather than use of the learning feature specifically.
- Undo is the least-served property. Where reversal exists it is "edit the markdown yourself" or git history on a project file; no Claude Code tool here keeps a write manifest or offers uninstall of what it learned.
- Anthropic's `claude-code-setup` is the closest official analogue to kh-harness's inventory step, but it stops at recommendation and writes nothing.

### Gaps
- I could not confirm an official documentation page for `/insights` or for an "auto dream" consolidation feature in Claude Code; third-party sources conflict on whether auto dream is shipped, flagged or absent, so it is not listed as a finding.
- ECC's README was only partly read (first 100,000 characters); approval and rollback being "not described" applies to the SKILL.md and that portion of the README.
- No install or active-user figures were found for any plugin; stars are the only adoption signal recorded.
- I did not verify mechanisms for the memory layers listed only by tagline (Hindsight, OpenViking, memsearch, supermemory, basic-memory, mcp-memory-service, beads), nor for severity1/claude-code-auto-memory and CodeYam Memory.

## 2. Which agent frameworks ship self-improvement as a feature, and what evidence do they give?

### Takeaway
Hermes Agent and Letta Code are the two products that make autonomous self-modification a headline feature, and both have had to add lifecycle machinery (curator, git-backed memory) to contain it. Evidence of benefit is almost entirely vendor-stated benchmark deltas; I found no independent measurement that a learning loop improves coding outcomes over time.

### Cited Findings

- **Hermes Agent** (Nous Research): 264,153 stars, last push 2026-11-17, tagline "The agent that grows with you". Official docs describe a closed learning loop: agent-curated memory with periodic nudges, autonomous skill creation, skills refined during use, cross-session recall. — [NousResearch/hermes-agent](https://github.com/NousResearch/hermes-agent), [Hermes docs](https://hermes-agent.nousresearch.com/docs)
- Hermes skills live in `~/.hermes/skills/`; the agent "can modify or delete any skill" through a `skill_manage` tool (create, patch, delete, write_file, remove_file). Write approval is **off by default** (`skills.write_approval: false`); when enabled, writes are staged under `~/.hermes/pending/skills/` and reviewed with `/skills pending`, `/skills diff`, `/skills approve`, `/skills reject`. The gate does not cover edits made through generic file tools or the terminal. The `skill_manage` linter is advisory: warnings "never block a write". — [Hermes docs: skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)
- Hermes added a **curator** because "skills created via the self-improvement loop don't pile up forever"; without it "you end up with dozens of narrow near-duplicates that pollute the catalog and waste tokens". Deterministic lifecycle: stale after 14 days unused, archived after 30, never deleted. An LLM consolidation pass is "off by default because it costs aux-model tokens on every run and makes broad structural changes to your library". Before consolidation it takes a tar.gz snapshot; `hermes curator rollback` restores it, and a per-mutation audit ledger supports single-entry rollback. The docs page is internally inconsistent (another section says 30 and 90 days). — [Hermes docs: curator](https://hermes-agent.nousresearch.com/docs/user-guide/features/curator)
- A claim that Hermes "evaluates its own performance after every 15 tasks" appears in a single third-party article and is not in the official docs I read. — [ainauten](https://news.ainauten.com/en/story/how-hermes-ai-agent-learns-from-its-own-mistakes-rewrites-its-own-skills-after-every-15-tasks)
- **Letta Code**: 3,863 stars, last push 2026-11-17, tagline "Agents that self-improve with experience". "Agents programmatically rewrite their context to improve and adapt over time"; "All context (including memory blocks) is tracked via git" and can sync to a GitHub repository with `/memory-repository set`. "Sleep-time compute (now called 'dreaming')" is configured with `/sleeptime`; automatic client-side dreaming is off by default on native Windows. No benchmarks are cited in the README. — [letta-ai/letta-code](https://github.com/letta-ai/letta-code)
- Letta's dreaming docs: "Dreaming uses background subagents to review recent conversations, consolidate useful lessons, and update memory without interrupting your active work", triggered after a set number of agent steps or on compaction. An optional "Agent reviews before applying" mode has a second background conversation revise proposals; it does not ask the user for approval. — [Letta docs: sleep-time](https://docs.letta.com/guides/agents/architectures/sleeptime)
- The Letta server platform repository: 25,471 stars, last push 2026-10-18, "Platform for stateful agents: AI with advanced memory that can learn and self-improve over time". — [letta-ai/letta](https://github.com/letta-ai/letta)
- **OpenAI Codex**: 135,648 stars, last push 2026-11-17. Codex "can turn useful context from eligible prior chats into local memory files" under `~/.codex` (`memories_v2/`), generated in the background once a chat has been idle. "Local Codex memories are off by default." The docs say "Treat these files as generated state", that memories are a recall aid, and that required team guidance belongs in `AGENTS.md` or checked-in documentation. Chats that used external context (MCP, web search) can be excluded via `memories.disable_on_external_context`. — [openai/codex](https://github.com/openai/codex), [Codex memories docs](https://learn.chatgpt.com/docs/customization/memories?surface=app)
- **LangMem** (LangChain): 1,773 stars, last push 2026-11-16. Provides hot-path memory tools, a "Background memory manager that automatically extracts, consolidates, and updates agent knowledge", and tooling to "optimize agent behavior through prompt refinement". The landing page gives no benchmarks. — [langchain-ai/langmem](https://github.com/langchain-ai/langmem), [LangMem docs](https://langchain-ai.github.io/langmem/)
- **DSPy**: 39,112 stars, last push 2026-11-13. **GEPA**: 7,467 stars, last push 2026-11-09; "Optimize any text parameter — prompts, code, agent architectures, configurations" by having an LLM "read full execution traces" and propose targeted mutations with Pareto selection. It requires an evaluation metric. Vendor-stated results include "Coding agent resolve rate on Jinja via auto-learned skills" 55% to 82% and a DSPy program 67% to 93% on MATH. GEPA also ships as an Agent Skill installable in Claude Code. — [stanfordnlp/dspy](https://github.com/stanfordnlp/dspy), [gepa-ai/gepa](https://github.com/gepa-ai/gepa)
- **Mem0**: 69,120 stars, last push 2026-11-17. README reports 92.5 on LoCoMo and 94.4 on LongMemEval, with the caveat that "Scores reflect Mem0's managed platform, which includes proprietary optimizations not available in the open-source SDK". These are conversational-recall benchmarks, not coding outcomes. — [mem0ai/mem0](https://github.com/mem0ai/mem0)
- **Zep / Graphiti**: Graphiti has 32,889 stars, last push 2026-11-17; it builds "temporal knowledge graphs that evolve with every interaction — tracking what's true now and what was true before". — [getzep/graphiti](https://github.com/getzep/graphiti)
- **Cline Memory Bank** is "a documentation methodology", not a built-in feature: six markdown files in `memory-bank/` maintained through custom instructions in a rules file, updated when the user says "update memory bank" or after milestones. Cline: 71,712 stars, last push 2026-11-17. — [Cline docs: memory bank](https://docs.cline.bot/features/memory-bank), [cline/cline](https://github.com/cline/cline)
- **Roo Code** is archived (24,236 stars, last push 2026-05-15, `archived: true`), and the community roo-code-memory-bank repository last saw a push on 2025-05-15 (abandoned). — [RooCodeInc/Roo-Code](https://github.com/RooCodeInc/Roo-Code), [GreatScottyMac/roo-code-memory-bank](https://github.com/GreatScottyMac/roo-code-memory-bank)
- **Aider**: 50,157 stars, last push 2026-05-22 (about six months without a push; looks stalled). Its relevant feature is mechanical rather than learned: "Automatically lint and test your code every time aider makes changes. Aider can fix problems detected by your linters and test suites." — [Aider-AI/aider](https://github.com/Aider-AI/aider)
- **OpenHands**: 93,654 stars, last push 2026-11-17. **Goose**: 56,718 stars, last push 2026-11-17, now under `aaif-goose`. Adoption figures only; see Gaps. — [OpenHands/OpenHands](https://github.com/OpenHands/OpenHands), [aaif-goose/goose](https://github.com/aaif-goose/goose)

### Inferences
- Frameworks split into three families: (a) autonomous self-editing of skills or memory (Hermes, Letta Code, ECC), (b) generated recall state kept explicitly separate from rules (Codex memories, Claude Code auto memory, Mem0, Zep), and (c) metric-driven optimisation of text (DSPy/GEPA, LangMem's prompt optimiser). Only family (c) has a built-in notion of "did the change help", and it needs an evaluation set that ordinary repositories do not have.
- OpenAI and Anthropic both draw the same line in their docs: learned memory is advisory recall, and anything mandatory belongs in checked-in instructions or hooks. A self-improvement feature that promotes a learning into a check sits on the side of that line the vendors leave to users.
- Hermes is the strongest evidence that unbounded self-authoring produces clutter: the vendor shipped a default-on curator, an archive-never-delete policy, snapshots and an audit ledger after the fact. Its rollback design (snapshot before structural change, per-entry ledger) is the closest prior art to a manifest-backed undo.
- Git-backed memory (Letta Code) gives history, but history is not the same as a scoped undo of one learning plus everything derived from it.

### Gaps
- I could not verify from primary sources what OpenHands and Goose currently ship for learning from sessions. Search results mention OpenHands repository microagents and an agent-memory skill that persists knowledge to AGENTS.md, and Goose "recipes", but only from third-party pages.
- No independent, longitudinal evaluation of any framework's learning loop on coding tasks was found. GEPA's and Mem0's numbers are self-reported; I did not open the linked methodology.
- LangMem's prompt-optimisation algorithms and any procedural-memory evidence were not on the page read.
- OpenAI Agents SDK was not researched separately from Codex.

## 3. Which tools turn observed agent mistakes into mechanical enforcement, and is anyone closing the loop from "told rule" to "enforced rule" automatically?

### Takeaway
A few tools generate enforcement from mistakes, but each covers one narrow enforcer (regex tool-call gates) and none ties a rule to its enforcer in a registry or generates lint rules and tests reliably. The most telling data point is that ECC, with 305K stars, still had "enforce high-confidence instincts at PreToolUse" as an open pull request in November 2026.

### Cited Findings

- **hookify** (Anthropic official plugin): "Easily create custom hooks to prevent unwanted behaviors by analyzing conversation patterns or from explicit instructions." `/hookify` with no arguments "analyzes recent conversation to find behaviors you've corrected or been frustrated by". Rules are markdown files with YAML frontmatter at `.claude/hookify.<name>.local.md`, with `event` (bash, file, stop, prompt, all), a Python regex `pattern` or field conditions, and `action: warn` (default) or `block`. Rules take effect without restart and can be toggled via `/hookify:configure`. It is manually invoked and regex-only. — [hookify README](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/hookify)
- **ECC pull request #3189** (open, opened 2026-09-20, 175 comments as of 2026-11-18) states the problem directly: "Instincts learned by continuous-learning-v2 are injected at SessionStart and then ignored at tool time ... SessionStart text does not stop a later Write that repeats a named mistake." It proposes a PreToolUse hook that blocks (exit 2) when instinct confidence >= 0.85 and a deterministic payload match occurs, warns at 0.70-0.84, and can be disabled with `ECC_INSTINCT_ENFORCE=0`. — [affaan-m/ECC PR #3189](https://github.com/affaan-m/ECC/pull/3189)
- **ThumbGate** (IgorGanapolsky): 31 stars, last push 2026-11-16. "Accepted feedback is stored as local lessons. Repeated concrete failures can become prevention rules that promote from warnings to blocking gates." Runs in the PreToolUse hook; installs MCP server plus PreToolUse, UserPromptSubmit, PostToolUse and SessionStart hooks. The guide says rules are generated automatically with "no manual rule writing needed", gate confidence adapts by Thompson Sampling, and storage is SQLite with FTS5. Commercial tiers: free with 5 active prevention rules, Pro $19/month, Team $49/seat/month. Its tagline: "A prompt is advice; a PreToolUse hook is enforcement." — [IgorGanapolsky/ThumbGate](https://github.com/IgorGanapolsky/ThumbGate), [ThumbGate guide](https://cdn.jsdelivr.net/npm/thumbgate@1.18.0/public/guide.html)
- Community skills that convert prose rules to enforcement exist but are small and unverified beyond catalogue listings: a `hookify` skill that reads CLAUDE.md or AGENTS.md and converts deterministic instructions into PreToolUse hook scripts; a `rule-toolkit` skill that generates ESLint, Prettier or commitlint config from instruction files; a `guardrail` skill that generates ESLint or ast-grep rules with tests. — [SkillsMP: monolab hookify](https://skillsmp.com/creators/pabloimrik17/monolab/claude-plugins-experiments-skills-hookify), [Implexa: rule-toolkit](https://implexa.ai/s/clawhub/rule-toolkit), [skills.sh: guardrail](https://skills.sh/phrazzld/claude-config/guardrail)
- Practitioner guidance treats promotion to enforcement as a manual discipline: Evil Martians advise asking the model to write a custom ESLint rule when it repeats an error, under the title "Stop writing rules in AGENTS.md: use agent hooks and nano-staged instead". — [Evil Martians](https://evilmartians.com/chronicles/stop-writing-rules-in-agents-md-use-agent-hooks-and-nano-staged-instead)
- A patterns guide describes an escalation path from suggestion to scoped context to skill to enforced hook. — [Proxify: system evolution](https://agentic.proxify.io/patterns/system-evolution)
- compound-engineering's experimental Compound Packs are rule folders "that planning grounds in and review enforces, every use cited back to the rule file": enforcement is by LLM review, not a mechanical check. — [EveryInc/compound-engineering-plugin](https://github.com/EveryInc/compound-engineering-plugin)
- Aider's lint-and-test-after-every-change loop is mechanical enforcement of existing checks, not generation of new ones. — [Aider-AI/aider](https://github.com/Aider-AI/aider)
- One search summary found "no evidence that Claude Code itself automatically writes lint rules from mistakes"; the official position is that hooks are the enforcement mechanism users must wire themselves. — [Claude Code docs: memory](https://code.claude.com/docs/en/memory)

### Inferences
- "Told rule to enforced rule" is closed automatically only for one enforcer class: regex or pattern gates on tool calls (hookify by command, ThumbGate by repeated failure, ECC proposed). Nobody found generates and validates lint rules, type-level constraints, tests or CI checks from observed mistakes as a maintained product; those appear only as blog advice and unverified catalogue skills.
- No tool found maintains an explicit mapping in which every rule names its enforcer and unenforced rules are visible as such. kh-harness's rules registry already has that shape, so "a learning is accepted only when it lands as a registry entry with a named enforcer, or is explicitly recorded as prose-only" is unoccupied positioning.
- Regex gates have an obvious false-positive risk, and neither hookify nor ThumbGate documents testing a generated rule against past sessions before activating it. Validating a proposed enforcer against recorded history (would it have fired on the mistake, would it have fired on good work) is not offered by anything here.
- ThumbGate's design is the nearest conceptual competitor to a learning-to-enforcement loop, but its adoption signal is negligible (31 stars) and it is a paid, MCP-plus-hooks product with dependencies.

### Gaps
- I could not verify the community `hookify`, `rule-toolkit` and `guardrail` skills from their source repositories, only from catalogue pages; treat their existence as likely and their quality as unknown.
- Whether ECC PR #3189 will merge, and what the 175 comments object to, was not read.
- I did not find any tool that generates tests from agent mistakes; absence of evidence within a limited search, not proof of absence.

## 4. Which tools assess or score "agent readiness" of a repository, and how do they differ from an inventory-and-install approach?

### Takeaway
Agent-readiness scoring is an established category led by Factory's commercial product and copied by several small open-source scorers. They measure against a fixed rubric and report a level or score; fixes, where offered, are agent-driven or template-driven with no documented manifest or uninstall, and none learns from the repository's own sessions.

### Cited Findings

- **Factory Agent Readiness**: five levels (Functional, Documented, Standardized, Optimized, Autonomous) across nine pillars (Style & Validation, Build System, Testing, Documentation, Development Environment, Debugging & Observability, Security, Task Discovery, Product & Experimentation). "To unlock a level, you must pass 80% of the criteria from the previous level." `/readiness-report` evaluates a repository in the Droid CLI or Factory app; `/readiness-fix` "automatically fix[es] failing criteria". The overview does not say whether evaluation is deterministic or LLM-based, what the fix writes, or whether it can be undone. — [Factory docs: agent readiness overview](https://docs.factory.com/agent-readiness/overview)
- Factory's marketing page lists eight pillars while the docs list nine. `/readiness-fix` "fetches the most recent stored readiness report for your repository and starts an agent session that works through the failing criteria"; organisation score is the average of repository levels rounded down. — [Factory product page](https://factory.ai/product/agent-readiness), [Factory docs: readiness report](https://docs.factory.ai/agent-readiness/readiness-report.md), [Factory docs: dashboard](https://docs.factory.ai/agent-readiness/dashboard)
- **kodustech/agent-readiness**: 138 stars, last push 2026-10-30, "The open-source alternative to Factory.ai's Agent Readiness". 39 checks across 7 pillars and 5 maturity levels with the same 80% gate. Most checks are deterministic file and config detection; four are AI-assisted and run only with `--ai`. Report-only (terminal, JSON, web dashboard, `--ci --min-level N`); no fixes. — [kodustech/agent-readiness](https://github.com/kodustech/agent-readiness)
- **ambient-code/agentready**: 157 stars, last push 2026-11-13. Weighted tiers (Tier 1 55%, Tier 2 27%, Tier 3 14%, Tier 4 4%) over 13 categories, certification levels Platinum to Bronze, HTML and markdown reports, attributes said to be backed by "50+ citations". No fix command documented in the README read. — [ambient-code/agentready](https://github.com/ambient-code/agentready)
- **0xmariowu/AgentLint**: 66 stars, last push 2026-11-13. "51 deterministic checks on 6 core dimensions, plus 7 opt-in extended checks (Deep + Session) that use AI sub-agents and local Claude Code session logs". An interactive `/al` flow: "Select items → AgentLint fixes → re-scores → saves HTML report". It is the only scorer found that reads session logs. — [0xmariowu/AgentLint](https://github.com/0xmariowu/AgentLint)
- **EShener/agent-ready**: 1 star. Zero-dependency CLI giving a "0-100 Agent Readiness Score with explainable deductions", "Local-first: no API key, no telemetry, no network calls". `fix` writes AGENTS.md plus shims for Claude, Cursor, Gemini and Copilot and a CI workflow; "Existing files are skipped unless `--force` is provided"; dry-run previews show files and estimated score gain. No undo command or manifest is described. — [EShener/agent-ready](https://github.com/EShener/agent-ready)
- **agentlint/agentlint**: 3 stars, last push 2026-11-16, "The Lighthouse for AI coding agents". — [agentlint/agentlint](https://github.com/agentlint/agentlint)
- Anthropic's `claude-code-setup` plugin is a read-only recommender of hooks, skills, MCP servers, subagents and commands for a codebase. — [claude-code-setup README](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/claude-code-setup)
- AGENTS.md itself is a widely adopted open format (agentsmd/agents.md: 25,532 stars, last push 2026-09-10), and Claude Code reads AGENTS.md in place of CLAUDE.md. — [agentsmd/agents.md](https://github.com/agentsmd/agents.md), [Claude Code docs: memory](https://code.claude.com/docs/en/memory)

### Inferences
- Scorers answer "how does this repository compare to a rubric"; kh-harness answers "what is missing, install only that, record it, and be able to remove it". The differentiators that no scorer documents are the write manifest and clean uninstall. agent-ready is closest in spirit (zero-dependency, skip-existing, dry-run) but has effectively no adoption and no uninstall.
- Scoring creates a target that can be gamed by generating files, and the ETH study in section 5 suggests generated context files can lower task success. A readiness score that rewards presence of AGENTS.md is weakly related to agent outcomes; an install approach that favours enforcers over prose avoids that failure mode.
- All rubrics are static. None adjusts what it recommends based on mistakes the agent actually made in this repository; AgentLint's opt-in session checks are the only step in that direction.
- Open-source scorers have very low adoption (1 to 157 stars) compared with the learning plugins, which suggests either the category is commercially captured by Factory or users do not seek scores on their own.

### Gaps
- Factory's criteria count, evaluation method and what `/readiness-fix` writes were not stated on the pages read; usage or customer numbers were not found.
- I did not verify other scorers surfaced by search (ariscan, agentkit-cli, agent-readiness-scorecard, Larridin's checklist).
- ambient-code/agentready may have alignment or bootstrap commands not shown in the README portion read.

## 5. What do users complain about in these tools?

### Takeaway
The recurring complaints are instruction bloat and staleness, learnings that are injected but not obeyed, skill and memory sprawl, token and process overhead, and the security exposure of agent-writable memory and skills. Peer-reviewed evidence adds that LLM-generated context files tend to reduce task success while raising cost.

### Cited Findings

- **Generated context can hurt.** "Evaluating AGENTS.md: Are Repository-Level Context Files Helpful for Coding Agents?" (ETH Zurich and LogicStar.ai, arXiv 2602.11988, February 2026; listed at ICLR 2026) finds LLM-generated context files lower success by roughly 0.5% on SWE-bench Lite and 2% on AgentBench while raising inference cost by over 20%; developer-written files give modest gains (about 4% on AgentBench) at non-negligible cost. The authors recommend keeping human-written files to minimal requirements. Limitation: Python-only benchmarks. — [arXiv 2602.11988](https://arxiv.org/abs/2602.11988), [ICLR 2026 listing](https://iclr.cc/virtual/2026/10018749)
- **Bloat from append-only learning.** A claude-reflect user: "The tool currently appends learnings without any awareness of CLAUDE.md size limits" and asked for warnings above about 150 lines and a prune command so the loop "doesn't eventually degrade Claude's performance". — [claude-reflect issue #12](https://github.com/BayramAnnakov/claude-reflect/issues/12)
- Anthropic's docs agree on the mechanism: "Files over 200 lines consume more context and may reduce adherence." — [Claude Code docs: memory](https://code.claude.com/docs/en/memory)
- **Learnings are not obeyed.** ECC's own contributors: instincts "are injected at SessionStart and then ignored at tool time". — [affaan-m/ECC PR #3189](https://github.com/affaan-m/ECC/pull/3189)
- Issues filed against Claude Code report "Memory and instructions not effectively followed across sessions - repeated mistakes waste tokens and user time" and that Claude Code "ignores CLAUDE.md/memory" (third-party mirror of the issue tracker). — [claudeissues #59666](https://claudeissues.com/issue/59666-memory-and-instructions-not-effectively-followed-across-sessions-repeated-mistak), [claudeissues #57760](https://claudeissues.com/issue/57760-claude-code-ignores-claude-md-memory-and-suspected-opus-4-7-capability-regressio)
- **Skill sprawl and bad self-patches.** Hermes's own curator docs concede that without maintenance "you end up with dozens of narrow near-duplicates that pollute the catalog and waste tokens", and that LLM consolidation "makes broad structural changes to your library". — [Hermes docs: curator](https://hermes-agent.nousresearch.com/docs/user-guide/features/curator)
- Practitioner posts name the failure modes as flattering self-reviews, silent overwrites and skill bloat, and one author keeps Hermes self-improvement off for the first 14 days, arguing the agent "grades its own homework" (blog sources, not measured data). — [pickaxe.co](https://pickaxe.co/post/self-improving-ai-agents), [DEV: akaranjkar08](https://dev.to/akaranjkar08/i-keep-hermes-agents-self-improvement-off-for-the-first-14-days-heres-what-happens-when-i-dont-4agk)
- **Staleness.** A Hacker News commenter describes big memory and doc systems that quickly go stale as "at best useless and at worst actively harmful"; other posts note nothing breaks when a rule goes stale, so drift is invisible until an agent acts on it, and one author reports a file past 800 lines where the agent ignored some rules and overweighted others. — [Hacker News item 49959080](https://news.ycombinator.com/item?id=49959080), [Unblocked: rules-file rot](https://getunblocked.com/blog/rules-file-rot), [Addy Osmani: Audit your agent files](https://addyosmani.com/blog/audit-your-agent-files/)
- **Token and process overhead.** One user's analysis of 270 sessions attributed about 1.485M tokens to claude-mem against 20k for a lighter alternative, estimated 5-8k tokens overhead per session, and found orphaned worker processes from an older version (single user, competitor-authored comparison). — [claude-historian COMPARISON.md](https://glama.ai/mcp/servers/@Vvkmnn/claude-historian/blob/5523c7a4febebd9cb3e54990eb6bc693ee206aa5/COMPARISON.md)
- A Claude Code issue reports auto-memory files "loaded twice in git worktrees causing premature compaction and quota exhaustion" (third-party mirror). — [claudeissues #24283](https://claudeissues.com/issue/24283-bug-memory-files-loaded-twice-in-git-worktrees-causing-premature-compaction-and)
- A code-reading review of claude-mem is titled "great idea, poor implementation". — [DEV: veltrea_code](https://dev.to/veltrea_code/-reading-yc-backed-code-1-claude-mem-great-idea-poor-implementation-2mbi)
- **Platform and dependency friction.** ECC's observer "requires WSL2, Linux, or macOS, since native Windows kills the process"; Letta Code's automatic dreaming is off by default on native Windows; claude-mem auto-installs Bun and uv and has analytics on by default; claude-reflect needs Python and had hooks fail when `CLAUDE_PLUGIN_ROOT` was not set. — [ECC continuous-learning-v2](https://raw.githubusercontent.com/affaan-m/ECC/main/skills/continuous-learning-v2/SKILL.md), [letta-ai/letta-code](https://github.com/letta-ai/letta-code), [thedotmack/claude-mem](https://github.com/thedotmack/claude-mem), [claude-reflect issue #17](https://github.com/BayramAnnakov/claude-reflect/issues/17)
- **Approval fatigue versus unreviewed writes.** A critique of claude-reflect notes its manual review step "can introduce a workflow bottleneck", while Hermes ships with skill write approval off and Letta's review mode "does not ask you for approval". — [SourcePulse: claude-reflect](https://www.sourcepulse.org/projects/22176241), [Hermes docs: skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills), [Letta docs: sleep-time](https://docs.letta.com/guides/agents/architectures/sleeptime)
- **Security.** Snyk's ToxicSkills audit scanned 3,984 skills and found 76 confirmed malicious payloads, and reports attackers targeting agent memory files (SOUL.md, MEMORY.md) so that injected directives persist; other counts for the ClawHub campaigns differ by source (341 and 1,184 malicious skills). Recommended mitigation includes monitoring agent configuration files such as MEMORY.md for unauthorised changes. — [Snyk: SKILL.md shell access](https://snyk.io/articles/skill-md-shell-access/), [Forkast](https://forkast.news/ai-agent-skills-are-the-new-supply-chain-attack-vector-and-most-have-never-been-vetted)
- Vendors acknowledge the exposure: Codex docs say "Don't store secrets in memories" and allow excluding chats that used external context from memory generation; Hermes quarantines project skills with a dangerous scanner verdict; claude-mem warns to install only from the official package because look-alike packages exist. — [Codex memories docs](https://learn.chatgpt.com/docs/customization/memories?surface=app), [Hermes docs: skills](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills), [Augment Code on claude-mem](https://www.augmentcode.com/learn/claude-mem-persistent-memory-claude-code)
- **Unverified benefit.** pro-workflow's improvement claims are illustrative, and a guide to `/insights` warns its suggestions are "pattern-matched from repetition, not verified as correct". — [rohitg00/pro-workflow](https://github.com/rohitg00/pro-workflow), [vincentqiao blog](https://blog.vincentqiao.com/en/posts/claude-code-insights/)

### Inferences
- The complaints form one causal chain: learning loops append prose; prose grows; growth lowers adherence and raises cost; rules go stale silently; users lose trust and stop reviewing. Tools respond with dedupe and curators rather than by changing what a learning becomes.
- A self-improvement feature that writes little prose, prefers a checkable enforcer, and expires or retires rules addresses the measured problem (the ETH result) rather than the perceived one (forgetting).
- An agent-writable memory or skill directory is a persistence target for prompt injection. A manifest of every write, with integrity checks against it, is a direct mitigation that the surveyed learners do not offer.
- Zero dependencies and native Windows support are real differentiators given the documented friction in ECC, Letta Code, claude-mem and claude-reflect.

### Gaps
- I did not retrieve Reddit threads (r/ClaudeAI, r/ClaudeCode, r/LocalLLaMA); two searches returned no Reddit pages, so user sentiment here comes from GitHub issues, Hacker News snippets and blogs.
- The Claude Code issue citations are from a third-party mirror (claudeissues.com), not the GitHub issue pages themselves.
- No data on uninstall or abandonment rates for any plugin, and no quantified rate of wrong learnings.
- The security figures are from vendor research on skill registries (mainly OpenClaw's ClawHub); I found no documented incident of memory poisoning through a Claude Code learning plugin specifically.

## 6. Where is the clear whitespace: what does nobody do yet, or do reliably?

### Takeaway
Nobody found combines the four properties kh-harness already has (inventory first, install only what is missing, every write in a manifest, clean uninstall) with a learning loop whose output is an enforced rule rather than more prose. Each property exists somewhere in isolation; the combination, plus evidence that a learned change actually helped, is open.

### Cited Findings
These are the facts from earlier sections that bound the gap; each is cited there and repeated here for the report writer.

- Vendors define learned memory as advisory: Claude Code treats memory "as context, not enforced configuration" and Codex says memories are a recall aid with required guidance kept in AGENTS.md. — [Claude Code docs: memory](https://code.claude.com/docs/en/memory), [Codex memories docs](https://learn.chatgpt.com/docs/customization/memories?surface=app)
- The largest learner has not shipped enforcement of its learnings: ECC PR #3189 was still open on 2026-11-18. — [affaan-m/ECC PR #3189](https://github.com/affaan-m/ECC/pull/3189)
- Mistake-to-enforcer generation exists only for regex tool-call gates (hookify, manually invoked; ThumbGate, 31 stars). — [hookify README](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/hookify), [IgorGanapolsky/ThumbGate](https://github.com/IgorGanapolsky/ThumbGate)
- Undo of learned changes is documented only by Hermes (snapshot, restore, per-entry ledger rollback) and implied by Letta Code's git-tracked memory; claude-reflect, ECC, pro-workflow and claude-mem document none. — [Hermes docs: curator](https://hermes-agent.nousresearch.com/docs/user-guide/features/curator), [letta-ai/letta-code](https://github.com/letta-ai/letta-code), [BayramAnnakov/claude-reflect](https://github.com/BayramAnnakov/claude-reflect)
- Readiness tools are static rubrics; the one with a fix command and zero dependencies has no manifest or undo; Anthropic's recommender is read-only. — [EShener/agent-ready](https://github.com/EShener/agent-ready), [claude-code-setup README](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/claude-code-setup)
- Measured evidence says LLM-generated context reduces success and raises cost. — [arXiv 2602.11988](https://arxiv.org/abs/2602.11988)
- Only metric-driven optimisers (GEPA) verify that a change improved outcomes, and they need an evaluation metric. — [gepa-ai/gepa](https://github.com/gepa-ai/gepa)

### Inferences
What is already done well, and probably not worth rebuilding:
- Session recall and search (claude-mem, Claude Code auto memory, Codex memories).
- Correction capture with human approval into CLAUDE.md (claude-reflect, `/revise-claude-md`).
- Solution notes as plain files in the repository (compound-engineering's `docs/solutions/`).
- Regex gates created on request (hookify).
- Rubric scoring (Factory and its open-source imitators).

Open gaps, in rough order of how clearly the evidence supports them:
1. **Learning that terminates in a named enforcer.** No tool found requires each accepted learning to bind to a hook, lint rule, typecheck setting, test or CI check, with prose-only rules marked as unenforced. A rules registry where every rule names its enforcer is the missing data structure.
2. **Provenance and reversible learning.** No Claude Code tool records which session evidence produced a rule, what files were written for it, and how to remove exactly that. Hermes's ledger is the nearest prior art, in a different ecosystem.
3. **Validation before activation.** No tool replays a proposed gate against recorded sessions to show it would have caught the mistake and would not have blocked legitimate work.
4. **Measurement of effect.** No tool reports whether a rule's violation or correction rate fell after it was added; claims are illustrative. A harness that owns the enforcers can count firings.
5. **Retirement.** Only Hermes ages out learned artefacts, by usage. Nobody retires a rule because its enforcer has not fired, the code it referred to is gone, or it conflicts with another rule.
6. **Inventory-aware learning.** No learner checks what the repository already enforces before proposing something, so duplicates of existing lint rules are possible. Scorers inventory but do not learn; learners learn but do not inventory.
7. **Minimal-context bias.** Given the ETH result and the 200-line guidance, a learner that tries to reduce always-loaded prose over time (moving rules into enforcers or path-scoped files) runs against the append-only norm.
8. **Zero-dependency, native-Windows operation** with no daemon, database or telemetry, which the larger tools do not offer.
9. **Integrity of agent-writable configuration.** A manifest allows detection of harness or memory files changed outside the tool, which addresses the memory-poisoning concern.

Risks to the positioning:
- Anthropic could extend hookify or auto memory to close gap 1 for regex gates; hookify already analyses conversations for corrected behaviour.
- ECC merging PR #3189 would give a very widely installed bundle confidence-thresholded blocking, though without registry, provenance or undo as far as the PR body shows.
- The enforcer-generation step is the hard part: generated lint rules and regex gates can be wrong, and no surveyed tool demonstrates reliable generation.

### Gaps
- Whitespace claims rest on a bounded search (about 30 tool calls, GitHub plus docs plus a few web searches). Small or very recent projects that already combine these properties may exist and were not found; in particular I did not search the Claude Code plugin marketplaces exhaustively or read awesome-claude-code's listings (hesreallyhim/awesome-claude-code, 58,226 stars, observed 2026-11-18, was identified but not read).
- I did not examine commercial offerings beyond Factory and ThumbGate (for example Cursor, Devin, Augment, Amp or Copilot memory features), so the "nobody" statements apply to the Claude Code ecosystem and the open-source frameworks listed.
- No user research was found on whether developers want learnings to become blocking checks; demand for gap 1 is inferred from complaints, vendor guidance and ECC's open pull request.
